# Zircon 微内核 C++→Rust 改写方法论解读

## 背景

Google Research 于 2026-11-13 公布多智能体协作成果：把 Zircon 微内核剩余的 C++ 代码
重写为约 80 万行安全 Rust，并通过全部内核单元测试。

## 三个可复用的工程决策

1. **任务切给多个智能体**：不是一个大 Prompt 从 0 改到 1，而是把任务切碎，每个智能体
   只拿到本步骤所需文件与工具。
2. **候选由测试套件自动校验**：不靠智能体自我宣称「正确」，测试套件是唯一真值。
3. **另一组智能体复核**：候选通过测试后，再由另一组智能体复核，防单一智能体幻觉。

## 为什么这很难

操作系统内核是「高危代码」——一个 data race 或 use-after-free 就可能导致系统崩溃或安全
漏洞。能在这种代码上做「可验证的大规模改写」，说明这套方法已经把 AI 改代码的能力边界
推到了基础设施层。

## 复用要点

你不需要写内核也能用这套方法：任何「代码库规模大、正确性要求高」的迁移/重构，都能套
「切分 → 门禁 → 复核 → 回滚」的骨架。
