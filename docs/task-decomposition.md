# 任务切分

## 原理

大规模迁移最怕「一个大 Prompt 让模型从 0 改到 1」。正确做法是**先拆后改**：
按依赖关系把迁移切成细粒度子任务。

## 做法

- 以「源文件」为最小迁移单元，一个源文件 = 一个子任务；
- 用依赖图（#include / use 声明）标注子任务依赖，被依赖者先迁移；
- 每个子任务只绑定真正需要的 read_scope 和 tool_scope。

## 为什么这么做

粒度越细，失败影响面越小、越容易并行、越容易回滚。这跟「微服务」是同一个心智：
把大单体拆成小单元，每个单元独立、可验证、可替换。

## 复用要点

「先拆后改」几乎适用于所有 LLM 复杂任务——把大任务切成可独立验证的小步骤，
比一个超长 Prompt 一次到位可靠得多。
